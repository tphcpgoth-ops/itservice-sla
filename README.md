# Hospital IT Service Tracker (React + Node.js + MySQL + LINE Integration)

โปรเจ็คเว็บแอปพลิเคชันระบบงานแจ้งซ่อมบำรุงคอมพิวเตอร์และเทคโนโลยีสารสนเทศของโรงพยาบาล พร้อมเชื่อมต่อระบบการยืนยันตัวตนและการแจ้งเตือนผ่าน LINE Login & Messaging API โดยถอดแบบดีไซน์และความสวยงามพรีเมียมจากโปรเจ็ค Stitch (Hospital IT Service Tracker)

---

## 📂 โครงสร้างโฟลเดอร์ของระบบ (Project Structure)

ระบบได้รับการพัฒนาแบบ **Monorepo** เพื่อความเป็นระเบียบและจัดการได้ง่าย:
* 📁 `backend/` : Node.js Express API, การติดต่อ MySQL, เว็บบล็อก Webhook, ระบบความปลอดภัย JWT และ LINE API SDK
* 📁 `frontend/` : เว็บแอปพลิเคชันฝั่งหน้าบ้านสร้างด้วย Vite + React.js พร้อมระบบดีไซน์ Clinical Modern HSL ที่สวยงาม

---

## ⚡ วิธีการตั้งค่าและติดตั้งระบบ (Installation Guide)

### 1. นำเข้าข้อมูลระบบฐานข้อมูล MySQL
1. ตรวจสอบให้มั่นใจว่า MySQL Server ของคุณเปิดใช้งานอยู่ (โฮสต์: `127.0.0.1`, พอร์ตเริ่มต้น: `3306`)
2. สร้างฐานข้อมูลชื่อ `itservice` และรันคำสั่ง SQL จากไฟล์:
   👉 **`/backend/schema.sql`**
3. สคริปต์ดังกล่าวจะสร้างตาราง `users`, `tickets`, และ `ticket_logs` พร้อมข้อมูลตัวอย่าง (Seed Data) สำหรับการสาธิตอย่างครบถ้วน

### 2. ตั้งค่าและรันส่วนหลังบ้าน (Backend Server)
1. เปิด Terminal เข้าไปที่โฟลเดอร์ backend:
   ```bash
   cd backend
   ```
2. ไฟล์คอนฟิกภายนอก `.env` ถูกตั้งค่าความปลอดภัยเบื้องต้นไว้แล้ว คุณสามารถเปลี่ยนรหัสผ่าน MySQL (`DB_PASSWORD`) หรือระบุค่าคีย์ของ LINE API ได้ในนี้
3. เริ่มต้นติดตั้ง Node Modules และรันเซิร์ฟเวอร์ด้วยโหมดเดฟ:
   ```bash
   npm install
   npm run dev
   ```
   *เซิร์ฟเวอร์ของระบบหลังบ้านจะทำงานที่:* `http://localhost:5000`

### 3. ตั้งค่าและรันส่วนหน้าบ้าน (React Frontend)
1. เปิด Terminal อีกตัวหนึ่ง เข้าไปที่โฟลเดอร์ frontend:
   ```bash
   cd frontend
   ```
2. ทำการรันเพื่อเข้าสู่โหมดการพัฒนาระบบ:
   ```bash
   npm install
   npm run dev
   ```
   *เว็บเซิร์ฟเวอร์จะทำงานบนพอร์ตที่กำหนดโดย Vite (ปกติเป็น:* `http://localhost:5173` *หรือ* `http://localhost:3000`*)*

## 🔑 วิธีการเข้าใช้งานจำลองเพื่อการทดสอบ (Mock Login & Testing)

เพื่ออำนวยความสะดวกในระหว่างการพัฒนาและทดสอบ บนหน้าจอลงชื่อเข้าใช้งานมีทางเลือกให้กดปุ่ม **"เข้าสู่ระบบจำลอง (Mock Login)"** โดยสามารถเลือกเป็นสิทธิ์และยูสเซอร์ตัวแทนต่างๆ ดังนี้:
1. **นพ.สมชาย (ผู้ใช้งานทั่วไป - แผนก OPD):** มีความต้องการเปิดใบซ่อมใหม่ และดูหน้าประวัติตามแผนกของตนเอง
2. **พญ.วันดี (ผู้ใช้งานทั่วไป - แผนก IPD):** ใช้ทดสอบความแตกต่างของแผนกและการแยกข้อมูลความปลอดภัย
3. **ช่างเอก / ช่างบอย (ช่างไอที):** ใช้เข้าหน้าจอรับเรื่องซ่อมแซม กดเริ่มงาน ย้ายสเตตัสงาน (Timeline) และบันทึกผลงานซ่อม
4. **แอดมินหญิง (แอดมิน):** ใช้เข้าตรวจสอบสถิติกราฟความพร้อมใช้งาน และสรุปการประเมิน SLA Compliance ในแดชบอร์ดส่วนกลาง

## 💬 การเชื่อมระบบ LINE Developers (สำหรับการใช้งานจริง)

หากต้องการให้ทำงานร่วมกับ LINE OA และสแกนคิวอาร์โค้ดล็อกอินจริง ให้เข้าไปตั้งค่าที่ [LINE Developers Console](https://developers.line.biz/):
1. **LINE Login Channel:**
   * สร้าง Provider และเพิ่ม LINE Login Channel
   * ระบุ App Types: **Web App**
   * ใส่ Callback URL ในช่องตั้งค่าดังนี้: `http://localhost:5000/api/auth/line/callback`
   * คัดลอก `Channel ID` และ `Channel Secret` มาใส่ในไฟล์ `/backend/.env`
2. **LINE Messaging API Channel:**
   * สร้าง Messaging API Channel 
   * นำบาร์โค้ด LINE OA ไปเพิ่มเป็นเพื่อนบนมือถือ
   * ไปที่แท็บ **Messaging API** -> กดออกตัว **Channel Access Token (Long-Lived)** และคัดลอกค่ามาใส่ในไฟล์ `/backend/.env`
   * เปิดระบบ Webhook และระบุ URL เว็บบล็อก (เมื่อทำโปรเจกต์ขึ้น Cloud Staging): `https://yourdomain.com/api/line/webhook`
